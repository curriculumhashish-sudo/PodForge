# PaiAgent Studio 阶段总结

> 按「基础框架 → 工作流引擎 → 前端画布 → 测试功能 → 工具节点」五个阶段归档。
> 实际开发中引擎、画布与节点存在交叉迭代，本总结以最终交付物和验收结果为准。

## 阶段总览

| 阶段 | 名称 | 状态 | 核心交付 | 验收结论 |
| --- | --- | --- | --- | --- |
| 一 | 基础框架搭建 | 已完成 | 前后端工程、配置、存储基础、启动脚本 | 前后端可独立启动并互通 |
| 二 | 工作流引擎开发 | 已完成 | DAG 校验、稳定拓扑排序、流式执行器、REST API | 12 项单元测试通过 |
| 三 | 前端画布开发 | 已完成 | React Flow 画布、节点库、检查器、保存恢复 | 4 节点链路正常渲染与编辑 |
| 四 | 测试功能开发 | 已完成 | 调试抽屉、实时轨迹、播放器；自动化与端到端验证 | 输入文字可生成并播放播客 |
| 五 | 工具节点开发 | 已完成 | 超拟人音频合成节点、音色配置、音频服务 | 生成约 64 秒真实 MP3 |

最终形成一个可本地运行的完整闭环：

```text
画布编排 → 保存工作流 → 输入测试文字 → DAG 校验与执行
→ 流式轨迹 → 大模型口播稿 → Edge TTS 音频 → 在线播放/下载
```

## 第一阶段：基础框架搭建

### 目标

搭建前端、后端、数据目录与启动方式，让后续引擎和画布有稳定的运行底座。

### 主要工作

1. **后端基础**
   - 使用 FastAPI + Pydantic + Uvicorn，端口固定为 `8010`。
   - 建立 `app/` 分层：`engine/`、`nodes/`、配置、数据模型、存储和语音清单。
   - 建立 `backend/data/` 运行目录，启动时初始化音频目录与 SQLite。
   - 提供 `.env.example`，约定 OpenAI 兼容模型配置。
   - 配置 CORS，允许本地开发端口访问。

2. **前端基础**
   - 使用 React 19 + TypeScript + Vite 6，端口 `5180`。
   - 配置 `/api` 开发代理到 `127.0.0.1:8010`。
   - 建立严格 TypeScript 配置、构建脚本与类型检查脚本。
   - 选定 React Flow 12 作为画布底座。

3. **运行与工程化**
   - 提供 `setup.bat`：检测运行时、创建虚拟环境、安装依赖、生成 `.env`、运行检查。
   - 提供 `start.bat` 与两个服务启动脚本，自动寻找 Node 20+。
   - 增加 `.gitignore`，排除密钥、虚拟环境、依赖、构建产物和运行数据。
   - 补充 `README.md` 与项目结构说明。

### 关键决策

- 端口选择 `5180 / 8010`，避开本机已有服务使用的 `5173 / 8000`。
- 前端以后端为执行权威，避免把校验逻辑只放在浏览器。
- 数据目录、数据库和音频全部落在项目内，便于本地启动与清理。

### 交付与验收

| 项目 | 结果 |
| --- | --- |
| 后端健康检查 | `GET /api/health` 返回 200 |
| 前端页面 | `http://127.0.0.1:5180` 返回 200 |
| API 文档 | `http://127.0.0.1:8010/docs` 返回 200 |
| 一键安装 | `setup.bat` 完整执行成功 |
| 生产托管 | 构建后 FastAPI 可在 8010 直接托管前端 |

## 第二阶段：工作流引擎开发

### 目标

实现真正可执行的 DAG 引擎，而不是只做界面演示：校验图结构、确定执行顺序、执行节点并持续输出事件。

### 主要工作

1. **工作流数据模型**
   - 定义节点、连线、位置、工作流文档和运行请求。
   - 设置规模与长度上限：60 节点、120 连线、4000 字测试输入等。
   - 节点配置保存在 `data` 中，运行状态与文档分离。

2. **DAG 校验**
   - 必须有且仅有一个用户输入节点和一个结束节点。
   - 校验重复节点 ID、不支持的节点类型、指向不存在节点的连线、自连和重复连线。
   - 禁止用户输入有入边、结束节点有出边。
   - 校验从输入可达、且所有节点都能到达结束节点，拦截孤立节点和旁路。
   - 使用拓扑排序检测环路。

3. **稳定拓扑排序**
   - 基于入度和最小堆实现。
   - 排序键包含节点优先级、原始顺序和 ID，保证相同图结构得到确定的执行顺序。
   - 用户输入节点优先执行。
   - 支持一个节点接收多个上游结果，按入边顺序收集。

4. **执行器与事件流**
   - 每个节点统一返回 `NodeResult(text, audioUrl, provider, detail)`。
   - 通过 NDJSON 推送 `workflow_started / node_started / node_finished / node_failed / workflow_finished / workflow_failed`。
   - 节点失败立即中断，保留已完成节点的结果。
   - 区分业务错误与内部异常：业务错误返回中文提示，内部异常记录日志但不泄漏堆栈。
   - 节点耗时、最终输出和音频缺失警告随事件返回。

5. **基础 API**
   - 健康检查、工作室状态、音色列表。
   - 当前工作流的读取与保存。
   - 工作流运行流式接口。
   - 音频文件访问接口。

### 关键决策

- 先做完整校验再执行，避免执行到一半才发现图非法。
- 使用 NDJSON 而非一次性 JSON，使前端能实时反馈每个节点状态。
- 图校验、排序、执行器各自独立，节点只关心自身输入输出，便于后续扩展工具节点。

### 交付与验收

- 单元测试覆盖：合法链、分支顺序、缺失输入、环路、孤立节点、重复边、空输入、不支持类型等。
- 后端测试共 **12 项，全部通过**。
- 非法工作流会返回明确的中文错误，例如：
  - 「节点「大模型」未接入“用户输入 → 结束”主链路」
  - 「主链路中存在循环连线，请断开形成环路的连线」

代码：[`backend/app/engine/graph.py`](../backend/app/engine/graph.py)、[`backend/app/engine/executor.py`](../backend/app/engine/executor.py)

## 第三阶段：前端画布开发

### 目标

把引擎能力变成可操作、可理解的 Agent 流图执行面板。

### 主要工作

1. **画布与节点**
   - 使用 React Flow 搭建画布，支持缩放、平移、节点拖拽和端口连线。
   - 自定义四类节点卡片：用户输入、大模型、超拟人音频合成、结束。
   - 节点运行状态实时映射到画布：待运行、运行中、成功、失败。
   - 连线颜色随上下游状态变化，运行中的边显示流动效果。
   - 客户端阻止非法连线，包括自连、重复边和会形成环路的连接。

2. **节点库**
   - 左侧按「基础节点 / 大模型节点 / 工具节点」分组。
   - 支持拖拽入画布，也支持点击添加。
   - 边界节点不能重复添加，已有状态有明确标识。
   - 点击添加时自动寻找当前可视区域内的空白槽位，避免覆盖已有节点。

3. **节点检查器**
   - 未选中节点时展示工作流概览、运行链路、引擎能力与操作提示。
   - 大模型节点：模型名称、温度、系统提示词、恢复默认。
   - 语音节点：8 种中文音色、语速、音调、音色卡片。
   - 边界节点：说明输入来源或最终输出，并禁止删除。
   - 普通节点支持删除；删除后同步清理相关连线和运行状态。

4. **文档与状态管理**
   - `Studio` 统一管理节点、连线、名称、运行状态、保存状态和提示。
   - 文档签名用于判断未保存修改。
   - 保存到后端 SQLite，刷新页面后自动恢复。
   - 调试输入单独保存在浏览器本地。
   - 支持 `Ctrl/Cmd + S` 保存。

5. **视觉与布局**
   - 三栏布局：节点库、画布、检查器。
   - 建立完整的颜色、间距、卡片、按钮、表单和状态色设计系统。
   - 调试抽屉打开时自动缩短画布可视区域，使节点不会被抽屉遮挡。
   - 增加响应式断点与减少动画适配。

### 关键决策

- 节点运行状态与持久化数据分离，保证保存内容干净。
- 边界节点作为图的固定入口和出口，降低非法图结构的产生概率。
- 新增节点自动寻找空白区域，而不是简单堆在画布中央。
- 抽屉采用覆盖层 + 画布可视区域调整，兼顾大输入区和节点可读性。

### 交付与验收

- 默认工作流加载 4 节点、3 连线。
- 选中节点后检查器正确切换到对应配置。
- 保存后刷新，节点、名称和保存状态恢复。
- 抽屉关闭/重开时，画布扩展/收缩，节点始终可见。

代码：[`frontend/src/Studio.tsx`](../frontend/src/Studio.tsx)、[`frontend/src/components/FlowCanvas.tsx`](../frontend/src/components/FlowCanvas.tsx)、[`frontend/src/styles.css`](../frontend/src/styles.css)

## 第四阶段：测试功能开发

本阶段包含两部分：产品内的「调试测试能力」和交付前的「工程验证」。

### 4.1 调试抽屉

- 打开抽屉后可输入测试文字，支持示例话题一键填入。
- `Ctrl/Cmd + Enter` 直接运行。
- 运行中显示进度、当前阶段和停止按钮。
- 执行轨迹按节点实时展示：状态、耗时、provider、文本预览和错误。
- 运行结束后展示：
  - 口播稿全文折叠区。
  - 合成音频播放器。
  - 音色说明与下载入口。
  - 无音频、合成失败等提示。
- 运行结果自动滚动到最新步骤；测试输入自动保存到 `localStorage`。

### 4.2 音频播放器

- 自定义播客播放器，包含播放/暂停、时间、进度、波形和下载。
- 读取音频元数据后显示总时长；支持拖动进度。
- 播放被浏览器拦截、音频加载失败时给出可操作提示。

### 4.3 工程验证

| 验证项 | 方式 | 结果 |
| --- | --- | --- |
| 后端图校验与文本工具 | 12 项单元测试 | 全部通过 |
| 前端类型安全 | `npm run typecheck` | 通过 |
| 前端生产构建 | `npm run build` | 通过 |
| 完整运行链路 | 无头 Chrome 实际操作 | 4 节点成功，生成约 64 秒 MP3 |
| 音频访问 | HTTP 请求 | 200/206，支持播放进度 |
| 持久化 | 保存后刷新 | 工作流与保存状态恢复 |
| 非法工作流 | 增加孤立节点后运行 | 返回“未接入主链路”错误 |
| 抽屉交互 | 关闭/重开 | 画布伸缩正常，节点可见 |
| 控制台 | 浏览器日志 | 无 error、无失败请求 |

### 4.4 过程中发现并修复的问题

1. **调试抽屉遮挡画布节点**：打开时可视高度不足，节点被覆盖。改为画布区域随抽屉高度收缩，并在可见区域执行 fit view。
2. **新增节点与现有节点重叠**：改为扫描可视区域的空白槽位放置节点。
3. **播放器音色显示错误**：结束节点覆盖了 TTS 的 `detail`。改为继承带音频上游的音色说明。
4. **循环校验测试文案不一致**：统一为“主链路中存在循环连线”的提示。
5. **favicon 404**：补充 SVG 站点图标。
6. **画布在零尺寸视口下的警告**：确认为隐藏浏览器视口导致，并在正常桌面视口完成完整验证。

### 关键决策

- 把调试能力做进产品，而不是只提供 API 测试脚本。
- 用真实浏览器走完整链路，而不是仅依赖单元测试和构建成功。
- 自动化端到端脚本用于本次验收，未作为常驻 CI 用例提交；后续可独立补齐。

## 第五阶段：工具节点开发

### 目标

实现真正产出可播放播客的「超拟人音频合成」工具节点，并串通结果回传与播放。

### 主要工作

1. **音频合成节点**
   - 使用 `edge-tts` 调用 Edge Neural 中文语音。
   - 提供 8 种音色，覆盖女声与男声。
   - 支持语速 `-30% ～ +30%`、音调 `-50 ～ +50 Hz`，后端再次做边界裁剪。
   - 口播稿上限 3000 字，避免超长合成和资源占用。
   - 使用 UUID 生成 MP3 文件名，避免并发覆盖。
   - 失败自动重试 2 次，间隔 0.6 秒；失败清理残留文件并返回中文错误。
   - 成功返回相对音频地址和音色描述。

2. **节点配置界面**
   - 检查器中提供音色下拉、语速滑杆和音调滑杆。
   - 实时展示当前音色卡片和声音细节。
   - 提示在线合成可能需要短暂网络等待。
   - 音色列表由后端统一提供，前端保留兜底清单。

3. **音频服务**
   - 提供 `/api/audio/{uuid}.mp3`。
   - 严格校验 `32 位十六进制 + .mp3` 文件名并检查父目录，防止路径穿越。
   - 启动时清理超过 24 小时的音频。
   - 支持浏览器 Range 请求，保障播放器拖动与流式加载。

4. **结果回传**
   - 结束节点汇总上游文本、最新音频和音色说明。
   - 前端收到 `workflow_finished` 后更新播放器。
   - 支持在线播放、进度拖动与下载。

### 关键决策

- 选择 Edge TTS：无需密钥、中文自然度好，适合零配置演示；代价是必须联网。
- 把音色、语速、音调做成节点配置，而不是固定参数，体现工具节点的可编排性。
- 音频由后端生成并托管，前端只消费 URL，避免把大文件放进执行事件。

### 交付与验收

| 验证项 | 结果 |
| --- | --- |
| 真实音频生成 | 通过，约 64 秒、384 KB |
| 合成耗时 | 约 6–16 秒（视文本与网络） |
| 音色展示 | 晓晓 · 温暖自然 |
| 播放 | 播放状态与进度正常前进 |
| 下载 | `paiagent-podcast.mp3` |
| 音频访问 | 200 + 206 Partial Content |
| 失败路径 | 重试、清理残留、中文提示均具备 |

代码：[`backend/app/nodes/hyper_tts.py`](../backend/app/nodes/hyper_tts.py)、[`frontend/src/components/AudioPlayer.tsx`](../frontend/src/components/AudioPlayer.tsx)

## 五阶段之间的依赖关系

```text
第一阶段 基础框架
   ├─ 提供运行环境、配置、存储与 API 骨架
   ▼
第二阶段 工作流引擎
   ├─ 提供可执行的 DAG 与事件协议
   ▼
第三阶段 前端画布
   ├─ 提供可视化编排与保存恢复
   ▼
第四阶段 测试功能
   ├─ 提供产品内调试闭环与工程验收
   ▼
第五阶段 工具节点
   └─ 提供真实音频产出，闭合最终体验
```

- 引擎先定义节点契约，前端和工具节点都依赖该契约。
- 画布先保证图能保存和提交，调试抽屉才能稳定复用同一份文档。
- 工具节点同时依赖引擎的上游结果和前端播放器，是最后闭合产品体验的一环。
- 测试能力贯穿全部阶段，但集中在第四阶段做完整验收。

## 最终成果指标

- 完整链路：用户输入 → 大模型 → 超拟人音频合成 → 结束 → 播放/下载。
- 画布：4 类节点、节点库添加、配置编辑、连线校验、运行状态可视化。
- 引擎：完整 DAG 校验、稳定拓扑排序、NDJSON 流式事件、中文错误提示。
- 音频：真实 MP3 生成、8 种音色、语速/音调可调、24 小时清理。
- 持久化：SQLite 工作流保存与恢复，浏览器测试草稿持久化。
- 质量：12 项后端测试通过、TypeScript 与生产构建通过、真实浏览器端到端跑通。
- 文档：README、设计文档、阶段总结、一键安装与启动脚本。

## 当前边界与后续方向

1. 当前仅维护一份工作流，尚未提供多工作流列表与版本发布。
2. 端到端脚本未纳入常驻 CI，后续可接入 Playwright。
3. Edge TTS 依赖外网，离线场景需替换为本地 TTS。
4. 客户端停止运行后，服务端已发出的外部合成请求无法撤回。
5. 尚无用户体系与权限控制，定位为本地工具/内网演示版本。
