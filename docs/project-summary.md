## 一、项目背景与目标

PaiAgent Studio 是一个可在本地完整运行的 AI 播客 Agent 项目。项目目标不是做一个静态的画布演示，而是打通一条真实可执行的生产链路：

```text
画布编排 → 保存工作流 → 输入测试文字 → DAG 校验与执行
→ 实时执行轨迹 → 大模型口播稿 → 神经语音合成 → 在线播放/下载
```

围绕这一目标，项目需要同时解决四个问题：

1. **可编排**：用户能通过节点和连线搭建“用户输入 → 大模型 → 超拟人音频合成 → 结束”的流程。
2. **可执行**：后端真正理解图结构，校验合法性、确定执行顺序并运行节点。
3. **可观察**：运行过程中能看到每个节点的状态、耗时、输出和错误，而不是只等一个最终结果。
4. **可交付**：没有大模型密钥也能体验完整链路，语音合成产出真实可播放的 MP3。

│  │ 唯一入口/出口   │   │ userInput → llm → tts → end     │     │
│  │ 连通性、环路    │   │ NDJSON 事件推送                 │     │
│  └────────────────┘   └──────────────┬─────────────────┘     │
│                                      │                       │
│               ┌──────────────────────┼──────────────────┐    │
│               ▼                      ▼                  ▼    │

运行方式有两种：

- **开发模式**：前端 Vite `5180`，后端 Uvicorn `8010`，`/api` 由 Vite 代理。
- **生产模式**：执行前端构建后，仅启动后端，静态页面与 API 都由 `8010` 提供。

## 五、关键实现说明

### 5.1 可执行的 DAG 引擎

- 工作流必须有且仅有一个用户输入节点和一个结束节点。
- 用户输入不能有入边，结束节点不能有出边。
- 所有节点必须从输入节点可达，并且都能到达结束节点，孤立节点和旁路会被拒绝。
- 拒绝自连、重复连线、指向不存在节点的连线和不支持的节点类型。
- 使用基于入度和最小堆的拓扑排序，排序键包含节点优先级、原始顺序和节点 ID，保证同一图结构得到确定的执行顺序。
- 图结构上限为 60 个节点、120 条连线，避免异常请求消耗资源。

### 5.2 统一的节点契约

所有节点接收上游结果并返回统一结构：

```text
NodeResult(text, audioUrl, provider, detail)
```

节点只关心自己的输入与输出，图校验、排序和事件推送由引擎统一完成。这使新增节点时不需要修改前端执行逻辑，目前四类节点均遵循该契约。

### 5.3 流式执行与可观察性

后端以 `application/x-ndjson` 逐行推送事件：

```text
workflow_started → node_started → node_finished / node_failed
→ workflow_finished / workflow_failed
```

前端按行增量解析并实时更新画布节点状态、连线动画、执行轨迹和最终结果。节点失败会立即中断执行，已完成节点的输出仍会保留。

### 5.4 大模型的双模式

- **接入模式**：配置 `LLM_API_KEY` 后，调用 OpenAI 兼容的 Chat Completions 接口。
- **本地模式**：没有密钥时使用内置口播整理器，链路仍能完整生成音频，界面上以 `LOCAL SCRIPT` 标识。
- 模型名称、温度和系统提示词均可在节点检查器中配置；本地模式下这些参数不参与生成。
- 模型返回内容会清理 Markdown、表情符号等不适合朗读的元素，并限制在适合合成的长度内。

### 5.5 真实音频产出

- 使用 `edge-tts` 调用 Edge Neural 中文语音，提供 8 种女声与男声。
- 语速限制在 `-30% ～ +30%`，音调限制在 `-50 ～ +50 Hz`，后端再次裁剪越界值。
- 单次合成文本上限为 3000 字。
- 使用 UUID 命名 MP3，避免并发覆盖；失败时清理残留文件。
- 音频接口严格校验 `32 位十六进制 + .mp3` 文件名，支持浏览器 Range 请求。
- 服务启动时清理超过 24 小时的音频文件。

### 5.6 前端状态与持久化

- `Studio` 统一持有节点、连线、工作流名称、运行状态、保存状态与提示信息。
- 节点运行状态不写入持久化文档，保存内容只包含结构和配置。
- 通过文档签名判断是否存在未保存修改，顶栏展示“有未保存更改 / 已保存时间”。
- 保存写入后端 SQLite；刷新页面后读取并恢复当前工作流。
- 调试输入单独保存在浏览器 `localStorage`。

## 七、关键决策与权衡

| 决策 | 原因 | 代价 |
| --- | --- | --- |
| 使用自研 DAG 引擎 | 逻辑可控、依赖少、便于展示校验与事件协议 | 暂不具备并行调度、重试策略等高级能力 |
| 后端作为执行权威 | 防止只靠前端校验被绕过，保证保存与运行一致 | 前端需要维护一份请求模型 |
| 使用 NDJSON 而非一次性 JSON | 能实时反馈每个节点的执行过程 | 需要自行处理分块读取与增量解析 |
| 无 LLM 密钥时使用本地整理器 | 零配置即可体验完整链路 | 文案质量与可控性弱于真实模型 |
| 选择 Edge TTS | 无需密钥、中文自然度好、接入成本低 | 必须联网，离线不可用 |
| SQLite 保存单一当前工作流 | 满足本地工具定位，结构简单 | 暂无工作流列表、版本与发布概念 |
| 运行状态与文档分离 | 保存内容干净，运行结果不会污染工作流 | 刷新后运行状态不保留 |
| 音频由后端生成并托管 | 事件只传 URL，避免大文件进入流式响应 | 需要文件生命周期与清理策略 |

## 十、当前边界与后续方向

| 当前边界 | 影响 | 后续方向 |
| --- | --- | --- |
| 仅维护一份当前工作流 | 无法并行管理多个项目 | 增加工作流列表、草稿与版本发布 |
| 暂无用户体系与权限 | 定位为本地工具或内网演示 | 接入登录、项目空间与操作审计 |
| Edge TTS 依赖外网 | 离线环境无法合成 | 抽象 TTS Provider，接入本地语音服务 |
| 执行器按拓扑顺序串行执行 | 分支不会并行，长链路耗时累加 | 增加并行调度与节点级重试策略 |
| 停止运行只中止前端请求 | 服务端已发出的外部合成请求可能继续完成 | 增加任务队列、服务端取消与状态回收 |
| 端到端脚本未纳入 CI | 依赖人工执行回归 | 接入 Playwright 与持续集成 |
| 音频仅在服务启动时清理 | 长时间运行会累积文件 | 增加定时清理或手动清理入口 |

## 十一、交付结论

项目已完成从画布编排、DAG 执行、实时轨迹到真实音频播放的完整闭环，并通过后端单元测试、前端类型检查与生产构建、真实浏览器端到端验证。在未配置大模型密钥的情况下仍可零配置体验，配置密钥后可切换为真实大模型生成，具备继续扩展节点与接入更多工具的基础结构。
